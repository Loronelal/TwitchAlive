# Twitch Keep Alive + избранные игры

Расширение Chrome (Manifest V3) из двух частей:

| Файл | Что делает |
| --- | --- |
| `content.js` | старый «keep alive»: подмена видимости вкладки, блокировка паузы и таймеров, уведомления о конце стрима |
| `favorites.js` | локальное избранное игр для страницы дропов: ★ на карточке и пункт «Избранное» в хедере |

## Установка / обновление

1. `chrome://extensions` → включить «Режим разработчика».
2. «Загрузить распакованное расширение» → выбрать папку `TwitchAlive`.
   Если расширение уже загружено — нажать ⟳ (Обновить) на его карточке.
3. F5 на вкладке Twitch.

> Chrome не грузит расширение, если хоть один файл или папка внутри
> начинается с `_` (такие имена зарезервированы системой). Поэтому тестовая
> папка называется `dev`, а не `_dev`.

## Как пользоваться

Страница `https://www.twitch.tv/drops/campaigns`.

**Звёздочка на карточке.** Звёздочка стоит справа от названия игры, сразу за
последней буквой (даты справа не задевает, текст не сдвигает). Навести курсор
на карточку — появится ☆, клик добавляет игру в избранное (★ становится золотой
и видна всегда), повторный клик убирает.

**Пункт «★ Избранное (N)» в хедере** — встаёт последним в полосу вкладок
дропов («Инвентарь / Все кампании / Значок за посты в соцсетях»):

* клик — включает фильтр «только избранное»: на странице остаются карточки
  только избранных игр, пункт подсвечивается фиолетовым;
* стрелка ▾ — открывает список: названия с кнопкой «−», переключатель
  «Только избранное» и «Очистить список»;
* если избранное опустело (или его очистили), фильтр выключается сам,
  чтобы страница не осталась пустой.

Все наши кнопки живут **только на страницах `/drops`**: вне их (канал, лента,
каталог) ничего не рисуется. Вставка идёт в полосу вкладок, которая содержит
ссылки на `/drops`, — чужие `role="tablist"` не трогаются, а «плавающих»
кнопок поверх страницы больше нет.

## Инвентарь дропов: что уже получено

На `https://www.twitch.tv/drops/inventory` рядом с названием каждой кампании
появляется отметка, чтобы не пересматривать уже пройденное:

| Отметка | Значение |
| --- | --- |
| `✓ Получено` (зелёная) | все живые полоски прогресса на 100%, кнопок «Получить»/«Подключить» не осталось, либо полосок нет вовсе |
| `Забрать` (жёлтая) | просмотр закончен, но награду ещё нужно забрать/подключить |
| `Недоступно` (серая) | все награды кампании истекли, смотреть нечего |
| `85%` (серая) | кампания не досмотрена; число — ближайшая к завершению награда |

Награды, помеченные Twitch как «Эта награда больше недоступна.» (и затемнённые
через `inventory-opacity-2`), из расчёта **выкидываются**: такие полоски
(например, 85%, 56%, 42% в Osaka 2026) уже не досмотреть, и кампания не должна
из-за них навсегда висеть на 85%.

Плюс в хедере появляется вкладка **«✓ Готово (N)»**: клик прячет полученные
кампании (состояние запоминается), повторный клик показывает всё.

Отметки пересчитываются сами: когда прогресс доезжает до 100% (Twitch меняет
`aria-valuenow` у полоски) или когда появляется/исчезает кнопка награды.

## «Все кампании»: счётчик собранных наград

На `https://www.twitch.tv/drops/campaigns` рядом с названием каждой игры
появляется счётчик собранных наград: `3/5`, а если собрано всё — зелёное
`✓ 5/5`. Такой же счётчик стоит у названия самой кампании в раскрытом блоке
(«FH EntireDirectory Oct26 `1/3`»), рядом со списком наград. Наведение
показывает расшифровку и время, когда данные сняты с инвентаря.

Зелёным счётчик становится только когда собраны **все** награды: `✓ 5/5`.
Если часть наград истекла, остаётся серое `2/5` — зелёного «2 из 5» больше нет.

Что считается «собрано»: **сверка с блоком «Получено»** внизу инвентаря,
сначала по картинке награды, затем по названию. Это точнее полосок прогресса:
полоска может быть 100%, а награда ещё не забрана. Совпадение идёт с учётом
количества (если одна и та же награда получена дважды, она закроет две строки
кампании).

Полученные награды в раскрытых категориях подчёркнуты зелёной полосой —
видно, что именно уже забрано.

* Раскрыл кампанию на «Все кампании» — её счётчик и счётчик игры считаются
  прямо по видимым наградам этой кампании и списку «Получено». То есть цифры
  относятся именно к той кампании, на которую ты смотришь, а не к старой.
* Свернуто — показывается точный замер всей строки: он запоминается при
  первом чтении категории. Под одной шапкой Twitch иногда держит несколько
  кампаний (например, Cyberpunk 2077), поэтому замер строки хранится отдельно
  от кампаний и не даёт счётчику прыгать между ними.

### Кэш и пагинация

Инвентарь листается («Загрузить еще»), поэтому статистика **копится**, а не
перезаписывается: кампании, которые ушли с загруженной страницы, остаются в
кэше до 14 дней, а если кампании нет в текущем списке — «получено» всё равно
обновляется по блоку «Получено». Так счётчик не пропадает, когда список
разросся или страница перезагрузилась.

При открытии инвентаря расширение само нажимает «Загрузить еще» (до 8 раз за
визит), чтобы в кэш попали кампании со всех страниц, а не только первые пять.
В консоли это видно строкой `догрузка инвентаря: нажатий 3, кампаний 5 → 24`.

Если категории нет в инвентаре (по ней ещё не смотрели), счётчик появляется
сам: строки читаются по мере появления на экране (`IntersectionObserver`,
запас 300 px), а не пачкой по всей странице. Список у Twitch скроллится внутри
контейнера, поэтому событие `scroll` у окна не годится — наблюдатель видит
и такой скролл. В консоли: `прочитал по мере прокрутки: N`.

**Повторно строки не раскрываются**: точный замер строки (игра + дата
окончания) сохраняется в кэше, и обход её пропускает. Заново категория
читается только если замера нет, кэш протух (14 дней) или Twitch сменил
даты/награды (новый сезон — это новая кампания). Строки игр с несколькими
кампаниями читаются сразу при открытии страницы, не дожидаясь прокрутки.

Полный проход по всем строкам — вручную: стрелка ▾ у «★ Избранное» → кнопка
**«Собрать данные по всем играм»**. Она заново раскрывает и перечитывает все
избранные категории, даже если они уже в кэше; на длинной странице (100+
строк) это занимает около минуты.

Если блок раскрыть вручную, счётчик считается сразу.

Два нюанса:

* у каждой кампании хранится отпечаток набора наград. Если Twitch поменял
  награды (новый сезон/кампания под тем же названием), отпечаток другой —
  счётчики считаются заново, старые числа не подмешиваются;
* список «Получено» тоже копится: по каждому названию хранится максимум
  количества, поэтому подгрузка «Загрузить еще» не обнуляет прошлые находки.

Откуда данные:

1. **Инвентарь** при открытии считает статистику по играм и кампаниям и
   складывает её в `chrome.storage.local` (`inventoryStats`).
2. **GraphQL** — если операцию инвентаря уже подсмотрели (`gql-sniffer.js`
   в MAIN-мире запоминает `operationName` и `sha256Hash` запроса самой
   страницы), «Все кампании» повторяет этот запрос и берёт данные напрямую.
   Схема ответа включается только после самопроверки: на инвентаре разбор
   JSON сверяется с тем, что видно в DOM, и при совпадении запоминается.
3. **Разбор HTML** `/drops/inventory` — если GraphQL не ответил или схемы
   ещё нет.

Вкладка **«✓ Готово (N)»** там же прячет игры, где собрано всё.

Всё хранится в `chrome.storage.local` (`favoriteGames`, `onlyFavorites`) —
только в профиле браузера, на сервер ничего не уходит. Список общий для всех
вкладок Twitch: изменения подхватываются на лету.

Посмотреть из консоли страницы (контекст расширения):

```js
chrome.storage.local.get(['favoriteGames', 'onlyFavorites']).then(console.log)
```

## Как это устроено

* Игра определяется по `img[alt]` внутри `.accordion-header`, запасной
  вариант — первый `<p>`.
* Фильтр прячет обёртку заголовка вместе с блоком наград; стиль ставится
  inline — не зависит от CSP и хешированных классов Twitch.
* Пункт «Избранное» — `<li>` внутри `ul[role="tablist"]` (того, где есть
  ссылки на `/drops`). Если полосы вкладок на странице нет, кнопка вешается
  сверху справа, чтобы список оставался доступен.
* `MutationObserver` переприменяет фильтр после перерисовок React и заново
  вставляет вкладку, если Twitch её снёс. Реагирует только на узлы с
  карточками и на полосу вкладок — чат не грузит CPU.
* Кнопки и панель создаются в изолированном мире расширения, страница их
  не видит и не может сломать.

## Проверка

`dev/test.html` — копия разметки страницы дропов (включая настоящую полосу
вкладок) с ассертами. Поднять локальный сервер из папки проекта:

```powershell
python -m http.server 8123
```

и прогнать в headless Chrome:

```powershell
& "C:\Program Files\Google\Chrome\Application\chrome.exe" --headless=new --disable-gpu `
  --user-data-dir="$env:TEMP\tak" --virtual-time-budget=12000 --dump-dom `
  "http://127.0.0.1:8123/dev/test.html"
```

В конце DOM будет `<pre id="result">PASS</pre>` либо список упавших проверок.
`?both=1` — тот же тест вместе с `content.js`.
`dev/preview.html` — страница только для скриншота: `--screenshot=preview.png`.
Папку `dev` можно удалить, на работу расширения она не влияет.

## Про `content.js`

В нём есть две опасные для плеера вещи, которые стоит убрать, если дропы
считаются плохо:

* п.5 «защита от таймеров» — все `setTimeout`/`setInterval` обрезаются до 1 с:
  ломает буферизацию, рекламу и heartbeat дропов;
* п.4 — блокировка `HTMLMediaElement.prototype.pause` ломает кнопку паузы.

Избранное от них не зависит.
